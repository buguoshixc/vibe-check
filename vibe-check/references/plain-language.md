# 大白话对照表

## 术语 → 比方

| 术语 | 大白话 |
|---|---|
| API | 服务员：你点菜它去厨房取，你不用进厨房 |
| 数据库 | 账本／档案柜：专门存数据、以后能翻旧账的地方 |
| 框架 | 预制房：别人盖好的骨架，你在里面装修 |
| 库／依赖 | 借别人的零件：不用自己造，但零件坏了得等别人修 |
| 前端 | 店面装修：你看得见摸得着的部分 |
| 后端 | 后厨：看不见但真正干活的地方 |
| 服务器 | 一间一直开着的店：程序住在里面，别人随时能来 |
| 部署／上线 | 把店开出去，让别人能进来 |
| 本地运行 | 只在自己家里摆着，别人看不到 |
| 端口 | 门牌号：一台机器上不同程序各占一个号 |
| 缓存 | 便利贴：常用答案先记下，下次不用重算 |
| 回滚 | 后悔药／时光机：退回改动前的样子 |
| 重构 | 重新整理房间：东西没变，摆放更合理 |
| 编译 | 把菜谱翻译成厨师看得懂的话 |
| 报错／异常 | 机器罢工并举牌说明原因 |
| 日志 | 行车记录仪：出事了回放看发生了什么 |
| 测试 | 出厂前质检 |
| 环境变量 | 写在便签上的配置：换地方不用改代码 |
| 密钥／Token | 家门钥匙／门禁卡：谁拿到谁就能进你的门 |
| 版本控制／git | 游戏存档点：搞砸了读档重来 |
| 异步 | 取餐呼叫器：不用站着等，好了叫你 |
| 内存 vs 硬盘 | 脑子 vs 本子：关程序就忘 vs 一直在 |

表里没有的术语，现场打一个生活比方，别硬套。

## 方案对比五维度

| 维度 | 大白话定义 | 自查问题 |
|---|---|---|
| 成本 | 花不花钱、花多少时间 | 要买服务器／付费服务吗？搭起来要多久？学生预算默认≈0 |
| 依赖轻重 | 要装多少别的东西、会不会被绑死 | 装几个包？以后想换方案要重写多少？ |
| 能否回滚 | 搞砸了能不能退回 | 有存档吗？这步会删数据／花钱吗？ |
| 维护难度 | 以后改一个小功能要动几处 | 用户自己看得懂、改得动吗？ |
| 风险 | 最坏会发生什么 | 丢数据？泄露？白干一周？概率多大？ |

## 对比表模板

```
| | 方案A | 方案B |
|---|---|---|
| 成本 | … | … |
| 依赖轻重 | … | … |
| 能否回滚 | … | … |
| 维护难度 | … | … |
| 风险 | … | … |
```

每格 ≤20 字，不许出现没解释过的术语。格子放不下就挑最要紧的说。

## 推荐句式

> 我推荐 X。对你来说最重要的是<场景里最要紧的事>，X 在这点上<优势>。Y 的好处是<优点>，但代价是<大白话代价>。

推荐必须结合用户场景：课程作业／个人自用 → 简单优先；要上线给很多人用 → 才考虑更重的方案。
